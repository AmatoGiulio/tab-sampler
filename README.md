# Tab Sampler (working title)

A deliberately small Chrome audio sampler.

> **Naming:** `Tab Sampler` is a development codename only. A Chrome Web Store extension already uses that name, so choose a distinct public name before release.

**Click -> listen -> click -> trim -> loop -> export.**

The toolbar action is the recorder. There is no recording popup:

1. Click the extension icon to start capturing the current tab.
2. The icon turns red and pulses while capture is active.
3. Click the icon again to stop.
4. The editor popup opens automatically with the captured waveform.
5. Trim, audition/loop, and export a 32-bit float WAV.

## Status

Early V1. Capture, local PCM storage, native Web Audio playback, trim, zoom, loop, playhead, discard/new-capture flow, export, tests, CI, privacy posture, and motion primitives are in place. Real-browser QA and visual tuning remain ongoing.

Chrome 127+ is the initial target because the stop gesture uses `chrome.action.openPopup()`.

## Architecture

```text
Toolbar click
    |
    v
MV3 service worker
    |  tabCapture stream id
    v
Offscreen document
    |
    +--> AudioContext -> destination        (keep tab audible)
    |
    +--> AudioWorklet -> Float32 PCM chunks
                         |
                         v
                     IndexedDB
                         |
Second toolbar click     |
    |                    |
    +---- stop ----------+
    |
    v
Dynamic editor popup
    |
    +--> wavesurfer.js             (waveform / zoom / pan)
    +--> native Web Audio engine   (play / seek / loop)
    +--> @audio/encode-wav
    v
32-bit float WAV
```

The popup is assigned dynamically only after a recording has stopped. While recording, the action has no popup so `action.onClicked` remains the capture toggle.

See [docs/architecture.md](docs/architecture.md) for boundaries and extension points, and [docs/public-release.md](docs/public-release.md) for the Chrome Web Store posture.

## Stack

- **WXT + TypeScript**: MV3 scaffolding, entrypoints, build/publishing path.
- **React**: small editor UI only.
- **AudioWorklet**: real-time PCM capture off the main UI path.
- **IndexedDB + idb**: chunked local PCM storage instead of extension storage quotas.
- **wavesurfer.js**: waveform rendering plus viewport zoom/pan; trim handles are intentionally owned by the product UI so their hit targets and motion stay deterministic.
- **Native Web Audio playback engine**: deterministic PCM audition, seeking, and sample-accurate loop boundaries without coupling playback correctness to the waveform renderer.
- **@audio/encode-wav**: small zero-dependency WAV encoder.
- **Motion**: shared-shape SVG morphs for the small number of UI icon transitions.
- **@webext-core/messaging**: typed messages between background, offscreen, and popup contexts.

No content script, no host permissions, no remote service, and no analytics are required for V1.

## Development

Requirements:

- Node.js 22+
- Chrome 127+

```bash
npm install
npm run dev
```

For a production build:

```bash
npm run typecheck
npm test
npm run build
npm run zip
```

WXT writes the unpacked extension to its `.output` directory. Load that directory from `chrome://extensions` with Developer mode enabled.

## V1 scope

In scope:

- capture current-tab audio from an explicit toolbar click
- visible recording state in the toolbar icon
- PCM capture through AudioWorklet
- waveform
- direct IN/OUT trim
- play/pause
- loop selection
- visible playhead / seek indicator
- waveform zoom and pan
- discard current sample and return to a fresh capture
- 32-bit float WAV export

Not in V1:

- EQ / effects
- normalization
- pitch or time stretch
- BPM detection
- stem separation
- sample library/cloud sync
- content extraction or site-specific downloaders

The narrow scope is intentional. Those features can be layered later without changing the capture/storage domain boundaries.

## Quality and audio semantics

The recorder stores Float32 PCM generated by Web Audio and exports IEEE-float WAV. This avoids an additional lossy encode/decode cycle, but it cannot restore information already removed by the source service. A lossy stream remains lossy source material even when the resulting sample is stored as PCM.
